# OVO - AI 软件工作站与平滑切换

OVO作为 **AI 软件工作站**，可接入多款软件，通过「工作区」与统一入口实现**软件间平滑切换**。首个接入的软件为 **Cursor / 本助手**，后续可按同一规范接入更多软件。

---

## 一、工作站是什么

- **入口**：OVO左侧栏顶部的「🖥️ AI 软件工作站」面板。
- **已接入软件**：以卡片形式列出，每个软件提供若干**操作按钮**（如导出状态、打开项目、从工作区加载等）。
- **平滑切换**：在OVO中操作 → 状态写入 `ovo_workspace/` → 在另一软件（如 Cursor）中打开同一项目继续处理 → 结果写回工作区 → 回到OVO加载。无需重复配置，上下文通过工作区共享。

---

## 二、当前已接入：Cursor / 本助手

| 操作 | 说明 |
|------|------|
| **导出状态到工作区** | 将当前对话、多 tab、模型列表摘要写入 `ovo_workspace/state.json`，在 Cursor 中让 AI 读取后可基于OVO内容回答或写拓展代码。 |
| **采集本机状态** | 将本机系统、进程等信息写入 `ovo_workspace/computer_state.json`，供 Cursor 内 AI 分析。 |
| **复制项目路径（在 Cursor 中打开）** | 复制项目根目录绝对路径，在 Cursor 中「打开文件夹」粘贴即可打开同一项目，与OVO共享工作区。 |
| **从工作区加载并运行** | 指定文件名（如 `extension.js`），从 `ovo_workspace/` 读取并执行拓展代码（通常由 Cursor 内 AI 生成）。 |

详细用法见 [11-与Cursor联动](11-与Cursor联动.md)。

## 三、如何接入新软件

通过编辑项目根目录下的 **`integrated_apps.json`** 增加新条目，即可在工作站中显示新软件卡片并绑定操作。

### 配置文件结构

```json
{
  "apps": [
    {
      "id": "cursor",
      "name": "Cursor / 本助手",
      "description": "在 Cursor 中打开本项目，AI 可读取OVO状态并写入拓展代码，实现与OVO的平滑切换。",
      "icon": "🖥️",
      "workspaceFolder": "ovo_workspace",
      "actions": [
        { "id": "export_state", "label": "导出状态到工作区", "type": "api", "api": "export_state" },
        { "id": "collect_computer", "label": "采集本机状态", "type": "api", "api": "collect_computer_state" },
        { "id": "open_in_app", "label": "复制项目路径（在 Cursor 中打开）", "type": "copy_project_path" },
        { "id": "load_extension", "label": "从工作区加载并运行", "type": "load_workspace_file", "inputKey": "workspaceFileName", "buttonKey": "loadWorkspaceBtn" }
      ]
    }
  ]
}
```

### 字段说明

| 字段 | 说明 |
|------|------|
| `id` | 软件唯一标识，用于前端 data-app。 |
| `name` | 显示名称。 |
| `description` | 卡片下方简短说明。 |
| `icon` | 可选，卡片标题前图标（如 🖥️、📁）。 |
| `workspaceFolder` | 与该软件共享的工作区目录名（通常为 `ovo_workspace`）。 |
| `actions` | 操作数组，见下表。 |

### 操作类型（actions）

| type | 说明 | 前端行为 |
|------|------|----------|
| `api` | 调用后端已有接口 | `api: "export_state"` → POST /api/export-state；`api: "collect_computer_state"` → POST /api/collect-computer-state。 |
| `copy_project_path` | 复制项目根路径 | GET /api/project-path，将返回的 path 复制到剪贴板。 |
| `load_workspace_file` | 从工作区加载并执行 | 卡片内提供「文件名」输入框 + 按钮，请求 GET /api/workspace-file?name=xxx，执行返回的 JS 内容。 |

新增软件时，复制现有 `cursor` 条目，修改 `id`、`name`、`description`、`icon`，按需保留或删减 `actions`（例如只保留 `export_state` + `copy_project_path`）。若需新操作类型，需在前端 `initWorkstationPanel` 与后端中一并扩展。

## 四、后端接口（供扩展参考）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/integrated-apps` | GET | 返回 `integrated_apps.json` 中的 `apps` 列表，供工作站面板渲染。 |
| `/api/project-path` | GET | 返回 `{ "path": "项目根目录绝对路径" }`，供「复制路径」「在某某软件中打开」使用。 |
| `/api/export-state` | POST | 写入OVO状态到 `ovo_workspace/state.json`。 |
| `/api/collect-computer-state` | POST | 采集本机状态到 `ovo_workspace/computer_state.json`。 |
| `/api/workspace-file?name=xxx` | GET | 读取工作区内指定文件内容（用于加载并运行拓展）。 |

---

## 五、小结

- **工作站** = 左侧「AI 软件工作站」面板 + `integrated_apps.json` 中配置的已接入软件。
- **Cursor** 为第一个接入软件，通过导出状态、复制项目路径、从工作区加载拓展，实现与OVO的平滑切换。
- 接入新软件：在 `integrated_apps.json` 的 `apps` 中新增一项并配置 `actions` 即可，无需改代码即可出现新卡片（新操作类型需前后端配合扩展）。
